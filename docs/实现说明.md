# 实现说明

面向开发维护，说明当前实现方式与边界。使用与启动见 [README](../README.md)，进展见 [开发计划](../开发计划.md)。

## 解析流水线

单向流水线：页面块 → 版面识别 → 连续段落 → 逻辑表 → 结构树与阅读单元 → 检索片段 → 规则卡。章节与条款层级只在构建结构树时推导一次；正文只在阅读单元中存一份，逐字坐标只用于计算高亮，不入库。

- **逐页选择文字层或 OCR**：含图片且文字层不足 30 字的页面按 300 DPI 渲染后用 RapidOCR（PP-OCRv6 small，固定 3.10.0）识别；其余页面用 pdfplumber 提取。混合 PDF 不因个别扫描页而降级文字页。行内空格跳过后再与逐字结果对齐，保留逐字坐标。
- **段落与结构**：跨页条款、问答连续组装；页码、重复页边文字、独立脚注、目录导航作为原页块保留但不检索；效力段与尾部落款分开。章节依据明确编号识别（`第…章/节/条`、`一、`、`（一）`、`1.`），不把通知条目改写为正式章条。最近一级标题随直接引出的正文入块。
- **分点与帽句**：“第…条”条文或以冒号结尾的段落之后，从序号 1 开始、同种编号连续递增的分点成组；合计不超过 300 字整组一片，否则每个分点一片并带上帽句（帽句不单独检索、不重复高亮）。
- **边界**：只有版面推测或正文疑似未完时标记“边界不确定”。扫描解析适用于中文单栏材料，印章去除和 OCR 纠错未实现。

## 表格

- **文字页**：pdfplumber 按表格线找表（至少 2 行 2 列），按全部单元格边界切成规则网格，合并单元格的每一格指向同一来源框。
- **扫描页**：按表格线找有框线表格的区域，并入版面模型（RapidLayout CDLA）检出的表格区域；按 OCR 行估算倾角纠偏；同一高度附近的横线段合并定行线，竖线须两端顶到横线并占满所跨行高（排除文字竖笔画），按线段覆盖判断合并单元格；无表格线时用 SLANet+ 给出单元格与跨度；OCR 逐字中心点归格。表单照片、二维码等不合理区域不作表格，照旧按正文。版面与表格模型为本地 ONNX，由 `backend.prepare` 下载校验。
- **逻辑表**：段落序列中紧邻、相邻页且列边界一致（文字页容差 2 点、扫描页 6 点）的片段合为一张表；续页重复表头不作数据；分页截断的行标识列延续上页值并记录来源，数值列不填充。表头深度由顶部合并单元格决定、不越过首个纯数字行；表头末尾脚注编号去除；首行与数据同类时判为无表头。表前引导句（“…如下表：”）、单位与表后“注：”段分别作为说明、单位和表注。以上均为通用规则，不依赖具体表名。
- **字段表示**：横向合并单元格只算一个字段（字段名取共同上级表头），相邻同名列合为一个字段；连续序号列不参与检索。

## 检索片段与召回

- 片段受 512 token / 1000 字符限制，超长按句界拆分并关联原阅读单元。
- **小表**（整表检索文本 ≤400 token）：一个整表片段，各行片段作检索入口，命中任一行都返回整表。
- **大表**：信息卡（表名、所属、单位、列、行标识、表注）加逐行片段（前缀“表名（单位）”），都归到表格节点，搜索里一张表只占一个名额。命中时用查询词在单元格值里按表内稀有度筛行（先用精确分词的完整词，再用细分词；出现在一成以上且多于 3 行的词忽略；短词被更长命中词包含时不重复计分；保留得分不低于最高分六成的行，最多 3 行）；没筛到行时只给列名和部分行标识。多查询命中同表时合并各自筛出的行；不同文件的同一张表合并为一条并记入 `also_in`。
- **排序**：Jieba 分词 BM25 与本地 BGE 向量余弦相似度用 RRF 按阅读单元融合，每路最多 20 个单元；语义候选阈值 0.40。每个查询至少返回前 3 组，其后相似度比第一组低 0.15 以上的不返回，最多 6 组。阈值只用于召回，不代表答案置信度。
- 精确向量扫描与内存 BM25，面向小规模本地试用；片段分词结果按片段缓存在内存中。

## Agent

- `search_documents`：1～4 个不重复查询（每个 ≤300 字），可限定 `document_id`、`node_id`；每次模型响应只执行第一个搜索调用。合并去重后 1/2/3/4 个查询分别最多返回 6/10/15/20 组制度命中，另附每查询最多 3 条已发布经验和命中文件的规则卡（同一对话每份文件只附一次）。同一轮再次命中的相同片段标为 `reused`，不重发正文。
- `query_table`：按表格节点和关键词在单元格值中筛行（同一套稀有度规则，最多 20 行），返回字段、单位、表注、每行引用和被忽略的常见词，可只保留指定列。
- `ask_question`：向用户追问，用 Pydantic AI DeferredToolRequests / DeferredToolResults 暂停与恢复。
- 单轮连同追问续接沿用框架默认的 50 次模型请求上限，每次请求超时 120 秒；工具参数校验失败可在同一轮纠正两次。模型调用工具前说的话保存为该步的 `note`，正文只保存最后的回答。
- 经验与制度冲突时提示模型采用经验，同时列出双方原文与引用。

## 会话占用

同一会话用 `status` 控制生成：短事务内原子占用后再读历史并校验，校验失败回滚；模型调用与查资料全程 `running`，重复发送返回 409。追问时把工具历史、待答问题与 `waiting` 一起保存，只接受与全部待答问题对应的非空回答。停止会等旧任务收尾；服务重启把遗留的 `running` 标为 `interrupted`。只支持本地单进程。

## 日志

两种模式都写控制台与 `data/app/logs/server-时间-模式.txt`。`simple` 只记请求状态、会话完成与调用次数、错误类型。`detailed` 使用 Pydantic AI 原生 Instrumentation + OpenTelemetry（SimpleSpanProcessor / ConsoleSpanExporter），记录每次模型请求的指令、历史、工具定义与输出，以及工具参数和结果；不上传任何遥测服务，API 密钥替换为 `[REDACTED]`。阅读时：`chat 模型名` 的 `gen_ai.system_instructions` / `gen_ai.input.messages` / `gen_ai.output.messages` 为指令、输入、输出；`execute_tool 工具名` 的 `gen_ai.tool.call.arguments` / `gen_ai.tool.call.result` 为工具参数与结果；跨轮按 `gen_ai.conversation.id` 关联。

## 切分预览

`GET /api/documents/{id}/chunk-preview` 只读，所有登录用户可用：返回实际检索片段的正文、所属章节条款、页码和高亮位置；管理员另得 token 数、阅读边界、定位状态等诊断信息。正文按来源字符定位，表格标记实际来源单元格；无法可靠定位时提示，不猜测位置。聊天证据栏使用同一接口。

## 存储与索引版本

- 原 PDF、索引（`document_indexes` 按用途分列保存结构节点、阅读单元、逻辑表、原页块和规则卡）、检索片段（`index_chunks`，含 float32 向量与高亮区域）在同一 SQLite 事务中保存；上传失败不留半成品，删除与重置同步清理。
- 当前索引版本见 `backend/indexing/__init__.py` 的 `INDEX_VERSION`。节点 ID 含解析代次，旧 ID 不会误读新索引。
- 索引版本变化时，启动自检（`backend/preflight.py`）中止启动并列出过期文件；用户运行 `python -m backend.reindex`，在内存中用库中原 PDF 全部重新解析，成功后单个事务替换全部派生索引（含旧版遗留表），失败整体回滚，原 PDF、文档 ID、账号、会话和经验保留。
- 初始模拟制度按 SHA-256 去重导入并记录已导入；管理员删除后重启不会补回。
